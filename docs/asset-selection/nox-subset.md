# The NOX Essentials subset this project ships

Generated by `tools/assets/nox_select.py` from `Essentials_Series_NOX_SOUND`. `HOUSE-00277`.

**445 of 1644 files ship** — 234.8 MB of 24-bit source, before `convert_audio.py` takes it to 16-bit (`HOUSE-00278`). 624 are excluded by rule and 575 did not survive the measurements or the caps.

Every number here is measured from the file. Nothing was chosen by ear, and nothing about how *clean* a recording is has been assessed — that is what the shortest, longest, quietest and loudest columns are for.

## What it costs, and the one number that does not fit

| | Files | 16-bit bytes |
|---|---:|---:|
| One-shots (≤ 3 s) | 373 | 20.6 MB |
| Loops (> 3 s) | 72 | 135.7 MB |
| **Total** | **445** | **156.3 MB** |

`cna-house.md` §72 budgets *"~430 clips at 16-bit 44.1 kHz mono/stereo, ≈ 95 MB"*. This selection is 445 clips — the right count — and **156 MB**, which is 1.6× that budget.

The count is right and the size is not, and the reason is visible in the split above: **373 one-shots come to only 21 MB**, while 72 loops carry 1106 seconds and 136 MB. §72's figure works out to about 0.22 MB a clip, which is roughly one second of mono — it priced one-shots and did not price a 30-second stereo rain bed or a 108-second computer hum.

**Trimming every loop to 10 seconds brings the total to 91 MB**, inside the budget. Ten seconds of rain or of a fan does not read as a repeat behind everything else in a house; thirty is what the recordist supplied, not what the game needs. That is `HOUSE-00278`'s decision to make with `convert_audio.py --trim`, not this tool's — the selection is *which* files ship, and this is the measurement that tells the conversion what it has to achieve.

## How the files inside a cap were chosen

**Farthest-point sampling in (duration, RMS)**, starting from the median-duration file. Consecutive takes from one recording session are the most similar files in a group, so taking the first *N* is the one selection guaranteed to sound repetitive. Starting from the most typical file keeps the group sounding like itself; adding whichever remaining file is furthest from everything already chosen keeps the spread. It is deterministic — the inputs are sorted and ties break on the file name.
